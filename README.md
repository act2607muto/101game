# 101（ワンオーワン）

トランプゲーム「101」のオンライン対戦版。各自のスマホで2〜6人対戦できます。

## 遊び方
1. https://play101game.vercel.app/ を開く
2. 1人が「部屋をつくる」→ 表示された4桁コードを共有
3. 他の人は「コードで参加する」からコードを入力
4. ホストが「ゲームを始める」

## 部屋ごとのルール
ホストはロビーで、次のルールのありなしを部屋ごとに切り替えられます（最初はすべて「あり」＝標準ルール）。
- A を +11 にもできる／5 でパス／8 でスキップ／9 でリバース／10 を −10 にもできる（なしにすると、そのカードは数字の分だけ足す）
- ちょうど101で0に戻る（なしにすると、101のまま続行）
- 合計100でジョーカーなら一人勝ち（なしにすると、ジョーカーはいつも +50）
- 山札から引いてそのまま出せる（なしにすると、手札からしか出せない）

ゲーム中は変えられません。勝敗画面の「ルールを変える（ロビーへ）」でロビーに戻ると変えられます。ホストが最後に使ったルールは、その端末で次に部屋をつくるときにも使われます。ゲストはロビーとルール画面（?）で、その部屋のルールを確認できます。

## 公開
Vercel（https://play101game.vercel.app/）で公開しています。`main` に入れると自動で反映されます。
以前の GitHub Pages の URL（`https://act2607muto.github.io/101game/`）を開くと、招待リンクの `?join=` も含めて Vercel に転送されます。

## ホストがいなくなったとき
- ホストが「退出」したりタブを閉じたりすると、つながっている次の人がホストを引き継ぎます（誰もいなければ部屋を閉じます）
- ホストの通信が40秒以上途切れたときも、次の人が引き継ぎます
- 対戦中だった回は無効になり、新しいホストの「同じメンバーでもう一度」ですぐ再戦できます
- 元のホストが戻ってきたときは、参加画面にルームコードが入った状態になるので、「参加する」で戻れます

## ホーム画面に追加（PWA）
- Android（Chrome）：ホーム画面の「ホーム画面に追加」ボタン、またはメニューの「アプリをインストール」
- iPhone（Safari）：共有ボタン →「ホーム画面に追加」

追加すると、アプリのように全画面で開けます。対戦には通信が必要です。

`sw.js` を変えたときは、中の `CACHE` の名前（`101-v1` など）を新しくしてください。

## ファイル構成
- `index.html` … 画面とゲームのコード
- `js/dc-runtime.js` … 画面を描くための仕組み（Claude Design の書き出しに含まれていたもの。編集しない）
- `js/vendor/` … React 18.3.1
- `favicon.svg` / `og.png` … タブのアイコンと、リンクを共有したときの画像
- `manifest.webmanifest` / `sw.js` / `icons/` … ホーム画面に追加（PWA）するための設定・オフライン用キャッシュ・アイコン

フォントは Google Fonts から読み込みます。

## Firebase のデータ
- `rooms101/<ルームコード>/` … 部屋ごとのデータ
  - `host` … ホストのID（引き継ぎのときに書き換わる）
  - `state` … 全員が見る場の情報（手札と山札の中身は入れない）
  - `msgs` / `pres` / `hb` … 参加・操作の連絡、接続状況、ホストの生存確認
- `hands101/<ルームコード>/<プレイヤーID>` … ゲストそれぞれの手札（本人だけが読める）

## Firebase の設定
セキュリティルールは `database.rules.json` にあります。ほかの人の手札を読む・場の情報を書き換える・ホストを乗っ取る・他人の部屋を消す、といった操作を拒否します。匿名ログイン（Authentication →「匿名」）を有効にしておく必要があります。

### ルールの自動反映
`database.rules.json` を変えると、GitHub Actions（`.github/workflows/firebase-rules.yml`）が次のことをします。
- プルリクエスト：ルールを Firebase エミュレーターに読み込ませて、書き間違いがないか確認する（`scripts/check-rules.sh`。手元でも Node と Java があれば実行できる）
- `main` へのマージ：Firebase にルールを公開する

ルールとページは、マージしたときにほぼ同時に公開されます。そのため、新しいルールは「今公開中のページでも動く」ように書いてください（許可を広げるのが先、狭めるのはページの更新が行き渡ったあと）。

最初に一度だけ、次の設定が必要です。
1. Google Cloud Console（プロジェクト games-ba1fa）→ IAM と管理 → サービス アカウント → 作成。ロールは「Firebase Realtime Database 管理者」と「Firebase 閲覧者」
2. 作ったサービス アカウント →「鍵」→「鍵を追加」→ JSON。ダウンロードされたファイルの中身をコピーする
3. GitHub のこのリポジトリ → Settings → Secrets and variables → Actions →「New repository secret」。名前は `FIREBASE_SERVICE_ACCOUNT`、値に 2 の中身を貼る
4. Actions →「Firebase rules」→「Run workflow」で一度動かして、成功することを確認する

ダウンロードした JSON ファイルは、Secret に登録したら削除してください。
